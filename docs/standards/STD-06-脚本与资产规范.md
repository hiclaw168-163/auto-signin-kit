# 脚本与资产规范

## 一、bash 胶水脚本红线

仅以下情形允许新增 bash 脚本,且必须放 `glue/`(**例外**: 仓库根 `install.sh`
一键安装入口,职责仅 `uv sync` + `uv tool install --force`,无业务分支):

- 主体是一次性外部命令管道调用,无业务分支
- 被 CI/外部工具直接 source,不值得包一层 CLI 命令

要求: `#!/usr/bin/env bash` + `set -euo pipefail`;头部注释写功能与所属域;
**超 50 行或有 if 业务分支 → 必须改写成 CLI 命令**(脚本没有测试与门禁,
业务逻辑住脚本里就是住在门禁之外)。

## 二、文档管理(命名与 specs/plans 约束)

### 2.1 命名

`docs/` 下的成体系文档统一用**类型字母前缀 + 两位序号 + 主题**:

| 前缀 | 文档类别 | 例 |
|------|----------|-----|
| `STD-` | 主题细则/规范(本目录) | `docs/standards/STD-01-新增命令与域规范.md` |
| `SPEC-` | as-built 设计文档 | `docs/superpowers/specs/SPEC-01-架构设计.md` |
| `PLAN-` | 实现计划(历史) | `docs/superpowers/plans/PLAN-01-<域>.md` |
| `ADR-NNNN` | 架构决策记录 | `docs/adr/ADR-0001-<slug>.md` |
| `NOTE-` | 逆向取证 / 上游项目分析 | `docs/notes/NOTE-01-workbuddy上游项目分析.md` |

- 字母前缀让文档类别一眼可辨;序号固定阅读顺序,新文档接续现有编号,
  不跳号、不复用已删除文档的编号。
- 创建日期记录在索引表与文档正文头部,**不写进文件名**——日期型命名
  (`YYYY-MM-DD-主题.md`)会让目录变成按时间排序的流水账,找"现行规范"
  要靠人记日期。

### 2.2 specs(as-built)约束

specs 回答"**现在是什么**",与代码保持一致是硬要求:

- **失同步即 bug**: 重构、新域落地、数据/配置形态变化后,必须当次同步对应 SPEC
  (域清单、数据路径、配置键、变更记录),不攒到下一次。
- 头部三件套: `日期` / `状态`(待评审 | 已实现 | 已交付) / `关联`(相关 SPEC 链接)。
- 重大变更追加**变更记录**条目(日期 + 一句话),不重写正文历史段落。
- 一个域/横切机制一份 SPEC;整体架构只在一号 SPEC。

### 2.3 plans(实现计划)约束

plans 回答"**当时打算怎么做**",是执行前写的实现步骤:

- 计划完成后**正文冻结**,代码后来又变了也不回头改正文——它记录的是决策过程,
  现状以 SPEC 为准;只允许补头部元数据(对应规格/状态)。
- 头部必标: `> 对应规格: SPEC-NN · 状态: 已完成(落地日期)`;**一个 SPEC 一个 PLAN**,
  编号对齐(`PLAN-NN` ↔ `SPEC-NN`)。
- 项目早于规范建立、事后补记的计划,头部显式写"**回溯补记**",不伪造逐步历史。
- 内容至少四件: `Goal`(一句话) / `Architecture`(技术要点与取舍) /
  任务清单(Files + 步骤) / `验收`(基线比对、门禁)。

### 2.4 索引

- `specs/` 与 `plans/` 的上级目录一份 `README.md` 索引,表格列:
  文件 | 对应 SPEC(仅 plans) | 主题 | 日期;新增/重命名/拆分即同步。
- `docs/notes/` 一份 `README.md` 索引,表格列: 文件 | 取证对象 | 对应 SPEC;
  `NOTE-NN` 与域 SPEC 一一对应,新增取证文档接续编号并同步该表。

### 2.5 对账(无门禁,列入自查)

specs/plans 的内容一致性无法用 ruff/pytest 拦,列入人工自查清单:
每次重构或新域落地后,对照检查——域数量、数据/配置路径、域结构在 SPEC 中是否
仍然成立;发现失同步**当次修掉**。

## 三、数据放哪的判据

两类 "data" 不要混在一个地方,分界线是**共享性与数据性质**:

| 判据 | 放哪 | 加载方式 | 例子 |
|------|------|----------|------|
| **跨域共享**的资源数据(≥2 个域用) | `config/data/`(或随包 `assets/`) | 运行时按路径解析 + 惰性解析 + 缓存;可缺失、可降级 | 大体积查找表、字库、模板包 |
| **域私有**的小型内容目录(仅本域用) | `src/auto_signin_kit/domains/<域>/data.py` | import 静态常量,零 IO | 名称→字形映射、内置目录表 |

判断细节:

- 大体积(数百 KB 以上)/ gzip / 带独立许可证 / 用户可替换 → **数据文件**,不进 `.py`。
- 类型化、与域逻辑强耦合(名称即合法输入集合、顺序即输出顺序) → **域内 `data.py`**,
  随域测试一起跑,校验报错(列出全部合法名称)内聚在域内。
- 用户可改可扩展的 → `config/`(它是用户可见的配置面);
  用户不该随手改的 → 源码内常量。
- 第三方来源的数据文件,许可证文件放数据旁边一并入库。

## 四、依赖与资源分发

- 随包分发的静态资源经 `pyproject.toml` 的
  `[tool.hatch.build.targets.wheel.force-include]` 打进包内(模板里有注释示例),
  运行时路径解析"包内优先、仓库布局兜底"。
- 资源缺失的处理分两档: **必备资源缺失 → 显式报错**(`ConfigError`);
  **增强资源缺失 → 告警 + 降级路径**(如矢量图缺数据退回文字描述),
  不要把增强数据当必备数据用。
