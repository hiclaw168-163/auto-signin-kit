# ADR-0002-OS 差异收口 core/adapters;端口(ports)只在第二种实现出现时才建

- **状态**: 已接受并实现
- **日期**: 2026-10
- **关联**: SPEC-01 §4 · STD-05 · pyproject(import-linter 契约,ports 契约预写注释着)

## 背景

两个相邻问题:

1. `sys.platform`/注册表/DPAPI 这类 OS 差异写到哪?
2. 端口-适配器(Ports & Adapters)模式什么时候用?

## 决策

**OS 差异**: 只许出现在 `core/adapters/`(平台判定唯一在 `platform_info`;
凭据解密在 `win_dpapi`;日志目录在 `log_dir`;客户端发现/进程/注册表各自一个文件)。
门禁测试扫描 domains/ 全树禁止 `sys.platform` 等出现。

**端口策略**: 采用**显式判据**——"这类外部依赖将来会不会真出现第二种实现?
会,才在 `core/ports/` 定义 Protocol + `core/adapters/` 放实现;
这辈子只有一种实现的东西不套模式"(套模式不是免费的,过度抽象与写死一样是负担)。

当前盘点(全部单实现,故**不建 ports**):

| 外部依赖 | 现状 |
|----------|------|
| Qoder 凭据解锁 | DPAPI+GCM 一种 |
| Trae 登录态解锁 | SS_AES 一种(同为 win_dpapi 的 CBC) |
| WorkBuddy 解密 | 客户端运行时借力一种 |
| HTTP 客户端 | stdlib 一种 |
| 日志目录 | 三个平台一个函数表 |

## 结果与代价

- 好处: 架构负担最小;真需要时 ability 判断清晰(表里加一行)。
- 代价: 若某依赖出现第二实现,要补 `core/ports/` + 打开 import-linter 的
  "ports 不依赖 adapters"契约(已预写,注释着)。
- 门禁联动: `test_ports_do_not_import_adapters` 建目录即生效。
